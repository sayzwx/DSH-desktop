# DSH Desktop v0.8.2 发布说明

基线 v0.8.1 → v0.8.2。分支 `feat/p0-p1-p2-completion`。产物：
`dist/DSH-Desktop-v0.8.2-Setup.exe`（Inno 一键安装）、`dist/DSH-Desktop-v0.8.2.zip`。

本版是**主题迁移能力的全面扩展**：主题包识别从「绑死写法」改为「认产物证据」，
**市场 theme 分类实测 89.7%（140/156）可识别且可迁移**；同时修掉模型精修「跑成功但
什么都没带进来」的净化工序缺陷，并给迁移主题补上了**背景图**这块最大的短板。

## 一、主题包识别：支持六种形态（全量实测）

把市场 theme 分类 156 个 + 名字/描述像主题的 131 个（共 287 个）**全部拉下来逐个跑管线**
（审计脚本 `scripts/market-theme-coverage.cjs`，可复跑）。实测出的形态与支持情况：

| 形态 | 例子 | 支持 |
|---|---|---|
| `client.js` 内嵌 `SCHEMES` 字面量 | dsh-neo-skin | v0.7.x 起 |
| `src/schemes/*.tokens.json` 源码目录 | — | v0.8.0 起 |
| `skin.json` + bodyAttr + 整段 CSS | 官方皮肤生态（女仆工坊等） | v0.8.0 起 |
| **`bundle/client.js`（入口在 `exports["./client"]`）+ `ctx.theme.overrideTokens('ns', {…})` 调用参数** | dsh-kimino-theme（64 变量） | **本版** |
| **主题内容全在包内 .css 文件里** | hello-kitty（skin.css → 51 变量）、blackhole（89 变量） | **本版** |
| **`.tczp` 预设**（第三方主题引擎的 JSON 预设，内嵌 data: URI 壁纸） | dsh-vae-theme | **本版** |

配套改造：

- **入口按 package.json 解析**（`exports["./client"]` → `exports["."]` → `main/module` →
  常见候选 → 包内有界搜索），不再猜固定路径；
- **读全部客户端相关源码**（宿主半边 + 客户端半边 + 候选入口全并入——只读 `main` 会漏掉
  整个客户端半边）；
- **包内 .css 并入提取源**（`--dsw-*` 定义、body 背景、页面级规则都能从 css 文件里提取）；
- **平台判定改为看产物**：没有 `dsh.client` 声明时，只要有客户端产物源码就按 WebUI 插件
  处理（旧逻辑直接跳过 → 用户装了也搜不到）；界面会标注「平台按产物推断」；
- **通用变量提取**：任何 `--dsw-*` 键都捞，值支持对象字面量 / 简单 helper 调用 / 裸字面量 /
  CSS 文本；命名空间按调用点位置分组；
- **官方包全 scope 排除**（`@deepseek-ai/*` 是 token 的消费者不是主题，31 个官方组件不再
  误列成主题）。

**实测数字**：市场 theme 分类 **140/156 = 89.7%** 识别且全部可产出迁移
（token 型 77 / 通用型 47 / skin 型 16）。未识别的 16 个里约一半是市场分类标错的功能插件；
真正的机制特殊户约 8 个（patch-only 包、运行时动态拼 CSS 的）。

## 二、模型精修：修「跑成功但什么都没带进来」

v0.8.1 用户实测：精修提示完成，但产出为空。查主题库实录：**模型返回的 14 条产出全部被
净化丢弃**，丢弃原因清一色「token 名不合法：--panel / --text / --accent …」——
**模型给的是桌面端自己的变量，而净化只认 `--dsw-*`**。

对一个主题来说，很多观感（面板底色 / 文字 / 强调色）**没有对应的官方 `--dsw-*` 变量**，
直接给桌面端变量是唯一正确做法 —— 是我们的校验错了，不是模型。三处一起修：

1. **净化**接受「`--dsw-*` **或桌面端真实存在的变量**」（白名单 111 个，来自 styles.css；
   凭空造的变量名仍然拒绝）；
2. **应用**（`applyWebTheme`）此前同样只认 `--dsw-*` —— 就算过了净化也不会生效。现在
   桌面端变量也应用（先确认该变量在应用里真实存在）；
3. **提示词**明确写出两类都可以给。

另外：**精修结果如实汇报** —— 产出为空时提示「模型没有产出可用内容（被净化丢弃 N 处）
+ 首条原因」，不再一律弹「完成并已应用」。

## 三、主题背景图：有了挂载点，并且免费自动承接

用户实测「精修后还是没有背景」—— 模型自己写明「桌面端无对应挂载点」。**它是对的**：
迁移主题下 `#bgvideo`（视频壁纸）与 `#bgfx`（星域）都会被隐藏，桌面端**没有任何背景落点**，
连我们自己写的说明都在劝模型放弃资源迁移。

- **新增 `#themeBg` 主题背景层**（fixed 全屏 / cover 居中 / z-index 0 / 默认透明）；
- **页面级背景图免费自动承接**：皮肤底纹的写法是确定的 —— body/html 的 `background-image`。
  自动提取并挂到 `#themeBg`，**不用花模型的钱**。壁纸 URL 常是运行期虚拟路径
  （如 `/kimino-bg/current.jpg`），按**文件名**在包内兜底搜索解析成真实文件；
- **CSP 放行**：`img-src` 补上 `file:`（背景图受 img-src 管辖，此前主题包自带的
  图片/纹理会被静默拦掉），`font-src` 同理；
- `.tczp` 预设里内嵌的 data: URI 壁纸同样自动承接。

## 四、其它

- **快捷方式图标路径带版本号**（`app\ico\<版本>\DSH.ico`）：Windows 资源管理器按**路径**
  缓存图标，同一路径换图标文件后长期显示旧图；升级后走新路径，新图标立刻生效。
- 市场分类标错的功能插件（api-key-pool、sticky-notes 等）不会被列进主题列表。

## 安装

- **全新安装**：下载 `DSH-Desktop-v0.8.2-Setup.exe` 覆盖安装（引擎不打包进安装包，
  由安装器自动从官方源获取并构建）。
- **从 v0.8.0 / v0.8.1 升级**：应用内「检查更新」直接升级；若下载异常，到 Releases 页
  手动下载 `.exe` 覆盖安装。
- 国内加速：在官方链接前加镜像前缀，例如
  `https://ghfast.top/https://github.com/sayzwx/DSH-desktop/releases/download/v0.8.2/DSH-Desktop-v0.8.2-Setup.exe`

## 已知边界

- 「模型全文承接」依赖你自备的模型路由，会产生模型费用，由用户逐个主题自行决定；
- 未识别的约 10% 主题包以 patch-only / 运行时动态拼 CSS 为主（这类没有静态可提取的
  主题内容，需要逐包适配）；
- 动态壁纸（视频）仍由桌面端自己的层独占，迁移承接的是静态背景图。
