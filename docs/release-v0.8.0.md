# DSH Desktop v0.8.0 发布说明

基线 v0.7.1 → v0.8.0。分支 `feat/p0-p1-p2-completion`。产物：
`dist/DSH-Desktop-v0.8.0-Setup.exe`（Inno 一键安装）、`dist/DSH-Desktop-v0.8.0.zip`。

本版是**两个用户可感知缺陷的修复 + 主题能力的一次大扩展**。

## 一、修复：用户端自动更新「下到 100% 报错、又从 0 重下、一直重复」

这是本版最重要的一条 —— 它**决定了其它修复能不能到达用户**。

- **根因**：下载用 `AbortSignal.timeout(120000)` 给**整个下载**压了死线，而不是「停滞」超时。
  弱网下大文件必然在**收尾处**被掐断（进度条已走到 100% 附近）→ 报错 → 换镜像 → **从 0 重下**
  → 4 个加速镜像 + GitHub 直链共 5 跳全部同样断在收尾处 → 用户看到的就是「下到 100% 报错、
  一直重复」。开发机网快，120 秒足够下完，**所以本地复现不出来**。
- 改为：**连续 45 秒收不到字节才中止**（每收到一块就重置）+ 30 分钟绝对兜底；两个阈值可注入以便测试。
- **不校验就不算成功**：核对 `content-length`、拒绝过小文件、要求安装包时校验 PE 文件头（`MZ`）。
  镜像把 HTML 错误页当 200 返回是常事，这种东西绝不能流到「静默安装」。安装前再验一次。
- **断点续传**：某一跳失败不删半截文件，下一跳带 `Range` 接着下；能否当续传前缀看**文件头**
  而不是「流有没有走完」（服务端提前收尾时流是异常结束的，但已落盘的往往是好字节）。
- **下载目录兜底真的生效**：原先 `LAYOUT_ROOT\updates` 创建失败时会去建 `%TEMP%\DSH-update`，
  但写入目标仍指向建失败的那个目录 —— 装在 `C:\Program Files\...` 的用户每次写盘必失败。
- **安装器不再「启动即退出」**：`spawn` 只保证进程创建动作完成，文件不可执行是**异步**报错的。
  原先无条件 `app.exit(0)`，用户拿到坏文件时应用退出后**再也起不来**；现在等 `spawn` / `error` 再决定。
- **界面也是修复的一部分**：换镜像时进度**不归零**，明确说明「哪一跳断了、断在几 %」；
  最终失败时逐跳列出每跳的原因。

> ⚠️ **注意**：本次更新本身仍要由**旧版本**的下载器完成，而旧版下载器正是有缺陷的那一个。
> 如果点「一键更新」反复失败，请**到 Releases 页手动下载 `DSH-Desktop-v0.8.0-Setup.exe` 覆盖安装**。
> 装上 v0.8.0 之后，后续所有更新都会走新的下载逻辑。

## 二、修复：消息重复显示（每条消息正好两份）

用户长期反馈的「显示框重复」：同一个用户气泡、同一条回合统计框、同一条权限告警
（⚠ 权限预设已变更为… / ⚠ 沙箱模式已变更为… / ⚠ 审批策略已变更为…）各出现两份。

三条缺陷叠加：

1. **主进程建了两条事件流连接**。去重判据只挡 `readyState === 1`（已连接），而建连入口会被
   两条独立路径触发（主进程自己发现引擎就绪、渲染层请求连接），两者只隔一次 IPC 往返，
   而到 127.0.0.1 的 WebSocket 握手至少跨一个宏任务 —— 第二次调用看到的是一条**握手中**的连接，
   于是又建一条。**引擎的事件流在连接建立时会自动为所有会话订阅**，所以多一条连接 =
   每个事件都被投递两遍。
2. **渲染层没有事件级去重**。原有的去重只覆盖带消息 id 的 `user/message`、`assistant/message`；
   `turn/end`、`permission/preset`、`sandbox/mode`、`approval/policy`、`tool/call`、`hook/*`
   完全没有去重。
3. 历史窗口重绘时会清空去重集合，重连补发的帧会被当成新事件再画一遍。

修复：连接侧保证「同一事件流只允许一条活连接」（握手中也算），并加兜底不变量与回归日志；
渲染层按**事件 `seq`** 去重（引擎契约里 seq 会话内唯一且单调递增，与官方 Web 客户端同一判据），
判据是「**这个 seq 是否已经应用过**」而不是「是否大于水位」—— 两条连接交错投递会出现乱序，
纯水位会丢掉从未应用过的那条，**丢消息比重复显示更糟**。历史窗口里的 seq 也一并记账。

## 三、新增：主题工作室（把 WebUI 社区主题迁移到桌面端）

桌面端与 Web UI 是两套**零交叉**的配色命名空间，社区主题只改 Web 端，对桌面界面天生零效果。
主题工作室把这类主题带到桌面端：

- **主题包 = 四层**（token / 结构层 / 方案层 / 行为层），不是一张配色表 —— 结构层与方案层一并承接，
  所以圆角、阴影、边框这些「形状」也跟着变，不只是换色。
- **免费主路径零模型调用**：主题包里的方案表是标准 JSON，走静态提取 + `JSON.parse`，
  **不执行第三方代码**。模型精修是**可选、有费用、由你决定**的一步。
- **行为层的如实交代**：开 / 关、方案切换、选择记忆由桌面端原生承担（每个方案档位就是一个独立下拉项）；
  而「把设置行注册进 WebUI 通用设置」「对第三方插件的 CSS 适配」桌面端没有落点 ——
  这一条会**明确写在界面上**，不假装承接。
- 迁移主题只作用于自己的主题档位，**对内置主题影响为零**；移除后变量与结构层全部撤销，无残留。

## 四、主题：四套内置主题 + token 化重构

- 主题清单统一为 **浅色 `light` / 深色 `graphite` / 深空 `dark` / 自定义 `custom`**，
  移除紫月 / 极光 / 彗星金三套花哨皮肤。**新装默认深色**；老用户的旧主题名自动回落到默认值
  （否则 `data-theme` 谁都匹配不上，整页只剩基础配色，看起来像主题坏了）。
- 前置重构：把写死的 289 条透明度色值提升为 CSS token（`color-mix` 在预乘空间插值，
  与 `transparent` 混合只改 alpha、不改色相）。逐元素 computed style 快照比对
  （774 元素 × 15 属性）证明对深空主题渲染等价：**0 条超出 1/255 的差异**。
- 铁律：发光只走 `--glow*`，底色与描边只走普通色 token —— 关霓虹时边框不会跟着一起消失。

## 五、插件市场：性能与「到底生效了没」

- 点进插件市场的最长停顿 **2583 ms → 83 ms**；单键搜索同步阻塞 **108.8 ms → 0.1–0.3 ms**；
  longtask 累计 **5616 ms → 142 ms**。做法：分批渲染（首批 48 + 底部哨兵自动续批）、
  搜索防抖、分类按钮按指纹缓存、事件全面委托（原先每次渲染要绑 8000+ 个监听器）、
  卡片加 `contain`、入场动画去掉全页 `blur`。
- **如实回答「插件下载成功了吗 / 为什么应用里没效果」**：实测证伪了「没下载成功」，
  真实原因是被装的皮肤声明为 Web 平台且**默认关闭**。市场页据此写清机制、
  给出「打开 WebUI 去开启」入口，并在安装 / 更新 / 卸载后给出**确切结论**
  （真等到市场就绪、复核插件状态后再报，而不是固定等 3.5 秒猜一个）。

## 六、其它修复

- **提供商管理**从设置模块拆成独立模块（`renderer/providers.js`，60 KB），并修掉拆分过程中
  暴露的多处既有漂移；`settings.js` 与安装副本逐字节对齐。
- **打包清单修复**：electron-builder 的 `build.files` 补上 `lib/**/*`。
  Windows 本地打包走整目录复制掩盖了这个问题，只有 mac / linux 包会少了 `require('./lib/…')`
  的目标文件、启动即崩。
- 测试基建：`scripts/smoke-renderer.cjs` 补上禁 GPU 开关与「子进程提前退出即报真因」，
  修掉本机 GPU 起不来时**静默退出、零输出**的假通过。

## 七、验证

新增 6 个可重复执行的测试脚本，**每一项都做过反向验证**（把修复还原后测试必须失败）：

| 脚本 | 覆盖 |
|---|---|
| `scripts/update-download-test.cjs` | 下载链路 8 项：404 换跳 / 长度不符 / HTML 错误页 / 中途卡死 / **慢速但活着必须成功** / 绝对兜底 / 断点续传逐字节一致 / 主目录不可写回退 |
| `scripts/update-electron-net-test.cjs` | 真 Electron `net.fetch` 5 项（含 body 适配器兜底） |
| `scripts/event-seq-test.cjs` | seq 水位 23 项：首达 / 重复 / 交错 / **乱序不丢事件** / 无 seq 放行 / 长会话有界 / 会话隔离 |
| `scripts/chat-stream-dedup-e2e.cjs` | 真实 Electron + 真实引擎：单次 / 并发二次 / 并发三次连接后活连接数恒为 2；每会话恰好一条订阅；无重复事件 seq |
| `scripts/chat-dup-frame-e2e.cjs` | 真实渲染层：同一帧投两遍后气泡 / 三条告警 / 助手正文各只有 1 份；新事件照常；乱序照常；历史与直播边界 |
| `scripts/theme-studio-e2e.cjs`、`scripts/theme-analyze-e2e.cjs` | 主题工作室扫描 → 迁移 → 生效 → 切换干净 → 移除干净；notes 如实记录 |

另有既有门禁全绿：`scripts/smoke-renderer.cjs`（全部渲染轨道 + 启动无错误）、
`scripts/settings-smoke.cjs`、`scripts/check-encoding.ps1`（打包前置，不通过不放行）。

## 八、已知限制

- 自动更新的修复**只对 v0.8.0 及之后的版本生效**；v0.7.1 及更早的用户若自动更新失败，
  请手动下载覆盖安装（见第一节提示）。
- Inno 安装包的静默覆盖安装依赖 Restart Manager 关闭并重启正在运行的应用；
  若安装程序被安全软件拦截，请以管理员身份重试。
- 主题工作室对「把设置行注册进 WebUI / 第三方插件 CSS 适配」两类行为**没有落点**，
  界面上会如实标注为无法承接，而不是假装成功。
- macOS / Linux 产物由 CI runner 产出，Windows 本地无法验证。
